== Requirements

* JDK 17.
* Android SDK with the platform set as `compileSdk` in `lib/build.gradle.kts`. Point to it from
  `local.properties` (`sdk.dir=...`).
* Node.js 20 or later, only to build the documentation.

== Building and testing

[source,bash]
----
# build the library and the sample app
./gradlew assembleDebug

# unit tests (Robolectric) and unit test coverage report
./gradlew :lib:testDebugUnitTest :lib:createDebugUnitTestCoverageReport

# instrumented tests (needs a device or emulator)
./gradlew connectedAndroidTest

# Android Lint
./gradlew lint

# API documentation (Dokka), written to lib/build/dokka/html
./gradlew :lib:dokkaGenerate
----

== Building the documentation

[source,bash]
----
cd docs
npm ci
npx antora antora-playbook.yml
npx pagefind --site build/site
----

The site is written to `docs/build/site`. Search only works when the site is served over HTTP, for example with
`python3 -m http.server 8089 --directory docs/build/site`.

== Branching and releases

The repository follows gitflow:

* `develop` is the integration branch. Feature branches (`feature/<issue>-<name>`) start from `develop` and are
  merged back into it with pull requests.
* `main` only receives releases. A release branch is created from `develop`, merged into `main` and tagged with the
  released version. CI then publishes the library to Maven Central and the documentation to GitHub Pages.
* After a release, an automated pull request brings the release changes and the next version back into `develop`.

== Contributing

* Every source and test file starts with the Apache License 2.0 header used across the repository.
* Every class, method and property has KDoc.
* When you change a documented example, change the tagged region in `DocumentationExamplesTest` and the matching file
  in `docs/modules/ROOT/examples` together. The test fails when they differ.
